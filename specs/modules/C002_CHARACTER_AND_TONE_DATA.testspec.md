# テスト仕様書：C002_CHARACTER_AND_TONE_DATA

## 概要 (Overview)
本仕様書は、キャラクター、ヒロイン、客タイプ、および口調ガイドの参照構造を定義し、キャラクターごとの口調のブレを防ぐためのデータ定義を記述する。

## 責任範囲 (Responsibility)
本モジュールは以下の責任を担う。

1.  **マスターデータの定義:** 主人公およびヒロインのキャラクターマスターデータ定義。
2.  **口調ガイドの定義:** キャラクターごとの口調ガイド（Tone Guide）の定義と、それらの参照設定。
3.  **整合性バリデーション:** キャラクターと口調ガイド間の整合性検証の提供。

## データ構造 (Data Structures)

### キャラクター (Character)
キャラクターデータ構造は以下の要素で構成される。

*   `characterId`: キャラクターID（例: `CH_NADIR`, `CH_HAKIMA`, `CH_MIRA`, `CH_DARIYA`）
*   `name`: 表示名
*   `role`: 役割（`protagonist` または `heroine`）
*   `toneGuideId`: 参照する口調ガイドID（`TG_` で始まるID）

### 口調ガイド (Tone Guide)
口調ガイドデータ構造は以下の要素で構成される。

*   `toneGuideId`: ユニークなID
*   `description`: 口調の特徴説明（テキスト記述）
*   `rules`: 口調のルール定義（通常ルートと追加ルートの差分を含む）

## マスターデータ制約 (Master Data Constraints)
以下の制約条件が満たされていることを保証する。

*   **主人公の定義:** `CH_NADIR` は唯一の主人公として定義される。
*   **ヒロインの定義:** `CH_HAKIMA`, `CH_MIRA`, `CH_DARIYA` の3名がヒロインとして定義される。
*   **参照整合性:** 全てのキャラクターは、必ず有効な `toneGuideId` を参照していること。
*   **シナリオ本文の除外:** シナリオ本文（具体的な会話や行動）は、このデータ構造自体には含まれないこと。

## 受入基準 (Acceptance Criteria)
以下の項目が満たされていることを確認する。

*   [ ] 主人公は `nadir` が1名のみ定義されていること。
*   [ ] ヒロインは `hakima`, `mira`, `dariya` の3名が定義されていること。
*   [ ] 全てのキャラクターが、有効な `toneGuideId` を参照していること。
*   [ ] 口調ガイドが、通常ルートと追加ルートの差分を保持していること。
*   [ ] カスタマータイプ（客タイプ）ごとに、対応する口調ガイドを参照できること。
*   [ ] シナリオ本文が、キャラクターおよび口調ガイドの定義内に含まれていないこと。
