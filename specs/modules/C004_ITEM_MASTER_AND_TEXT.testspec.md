# C004_アイテムマスター＆テキスト仕様書

## 概要 (Overview)
本仕様書は、ゲームシステムにおけるアイテムの基本データ（マスターデータ）と、それに対応する品質別テキスト（説明文）の定義に関する要件を記述する。
全10ジャンル、各5品目、5術理属性の組み合わせにより、合計250アイテムのデータ構造を定義する。

## 責任範囲 (Responsibility)
本仕様が定義するシステムは、以下の責任を果たす。

1. **アイテム分類の定義:** アイテムが属するジャンルと術理属性を定義する。
2. **アイテムマスター管理:** 250種類のアイテムマスターデータ（ID、名称、ランクなど）を管理する。
3. **テキスト提供:** 各アイテムに対し、品質別（Normal, Success, Great Success）のテキストを紐づけて提供する。
4. **データ整合性バリデーション:** アイテムマスターデータとテキストデータが正しく関連付けられていることを保証する。

## データ構造定義 (Data Structures)

### 1. アイテム分類 (Item Taxonomy)
アイテムが属するカテゴリを定義する。

*   **ジャンル (GENRES):**
    *   `ARM`, `FOD`, `MED`, `ADN`, `CLT`, `DAY`, `WRK`, `TRV`, `RIT`, `TRD` (計10)
*   **術理属性 (PRINCIPLES):**
    *   `AS`, `EL`, `LI`, `ME`, `SA` (計5)

### 2. アイテムIDフォーマット (Item ID Format)
アイテムを一意に識別するためのID形式を定義する。

*   **形式:** `IT_{GENRE}_{PRINCIPLE}_{INDEX}`
*   **構成要素:**
    *   `IT`: アイテム識別子（固定）
    *   `GENRE`: ジャンルID（上記リストより選択）
    *   `PRINCIPLE`: 術理属性ID（上記リストより選択）
    *   `INDEX`: 品目インデックス（`01` から `05` の5段階）

### 3. アイテムデータ構造 (Item Data Structure)
アイテムマスターデータが保持する情報。

| フィールド名 | 型 | 説明 |
| :--- | :--- | :--- |
| `itemId` | String | アイテムのユニークID (例: `IT_ARM_AS_01`) |
| `name` | String | アイテムの名称（例: "剣"） |
| `genre` | String | ジャンルID (上記リストより選択) |
| `principle` | String | 術理属性ID (上記リストより選択) |
| `rank` | Integer | ランク (1〜5) |

### 4. アイテムテキスト (Item Texts)
アイテムの品質別説明文を定義する。

*   **品質種別:**
    *   `normal`: 通常の出来栄え
    *   `success`: 成功
    *   `great_success`: 大成功

## 受入基準 (Acceptance Criteria)

以下の項目が満たされることをテストの前提とする。

*   [ ] **ジャンル定義:** `genre` は以下の10種類が全て定義されていること。
    *   `ARM`, `FOD`, `MED`, `ADN`, `CLT`, `DAY`, `WRK`, `TRV`, `RIT`, `TRD`
*   [ ] **術理属性定義:** `principle` は以下の5種類が全て定義されていること。
    *   `AS`, `EL`, `LI`, `ME`, `SA`
*   [ ] **品目数:** 各ジャンル（10種類）において、それぞれ5品目（`INDEX`）が定義されていること。
*   [ ] **アイテム総数:** 全体で250アイテム（10ジャンル × 5品目 × 5術理属性 = 250）が生成・参照可能であること。
*   [ ] **ID形式:** アイテムIDが `IT_{GENRE}_{PRINCIPLE}_{INDEX}` の形式に準拠していること。
*   [ ] **テキスト定義:** 各アイテムが、`normal`, `success`, `great_success` の3種類の品質別テキストを保持していること。
*   [ ] **分離性:** アイテムマスターデータ（ID, 名称, ランクなど）と、アイテムテキスト（品質別説明）が明確に分離されていること。

---
**補足:**
本仕様は、アイテムマスターデータとそれに対応するテキストデータが、上記定義に基づき完全に整合していることを保証する。
