# C007_QUIZ_REQUEST_MODEL テスト仕様書

## 概要 (Overview)
本仕様書は、クイズ生成リクエストの処理ロジックとデータ構造を定義する。クイズ生成の要件（客タイプ、要望テンプレート、条件）に基づき、正解アイテムと不正解アイテムを決定し、クイズデータ（質問）を生成する。

## 責任範囲 (Responsibility)
本モジュールは以下の責務を担う。

1.  **クイズ要望テンプレートの定義:** どのような条件でクイズを生成するかを定義する。
2.  **正解アイテムの判定:** 指定された条件（ジャンル、術理、ランク）を満たすアイテムを特定する。
3.  **2択クイズ生成:** 正解アイテムと不正解アイテムを決定し、クイズデータ（`Generated Question`）を生成する。
4.  **データ整合性バリデーション:** 生成されたクイズデータが全ての制約を満たしていることを保証する。

## データ構造定義 (Data Structures)

### 1. クイズ要望テンプレート (Quiz Request Template)
クイズ生成の依頼元となるデータ構造。

| フィールド名 | 型 | 説明 |
| :--- | :--- | :--- |
| `templateId` | ID | テンプレートのユニークID。 |
| `customerType` | Enum | 客タイプ（例: `STANDARD`, `HAKIMA`, `MIRA`, `DARIYA`）。 |
| `conditions` | Array | 判定条件の配列。 |
| `conditions[i].type` | Enum | 条件の種類 (`genre`, `principle`, `rank`)。 |
| `conditions[i].value` | Value | 条件値（例: ジャンル名、ランク名）。 |
| `text` | String | 画面に表示される要望テキスト（プレースホルダ対応可）。 |

### 2. 生成されたクイズ (Generated Question)
クイズ生成の結果として出力されるデータ構造。

| フィールド名 | 型 | 説明 |
| :--- | :--- | :--- |
| `questionId` | ID | 生成されたクイズのユニークID。 |
| `promptText` | String | 画面に表示される要望テキスト。 |
| `correctItemId` | ID | 正解アイテムのID。 |
| `wrongItemId` | ID | 不正解アイテムのID。 |
| `difficulty` | Enum | 難易度（例: `STANDARD`、`EXTRA`）。 |

## ロジック規則 (Logic Rules)

1.  **正解アイテム選定:**
    *   指定された全ての条件を満たすアイテムを、`C004` マスターデータから1つ選出する。
2.  **不正解アイテム選定:**
    *   条件の少なくとも1つを満たさないアイテムを、`C004` マスターデータから1つ選出する。
3.  **重複禁止:**
    *   正解アイテムと不正解アイテムは、必ず異なるアイテムIDでなければならない。

## 受入基準 (Acceptance Criteria)

以下の項目は、実装されたロジックが満たしていることを確認する。

- [ ] **条件の網羅性:** `conditionType` は `genre`, `principle`, `rank` の全てを処理できること。
- [ ] **難易度対応:**
    - [ ] MVP通常難易度では、原則として1条件（単一条件）の問題を生成できること。
    - [ ] `EXTRA` 難易度では、最大2条件を許可できること。
- [ ] **正解候補:** 各クイズの正解候補は必ず1つであること。
- [ ] **不正解候補:** 不正解候補は、正解候補と重複しないこと。
- [ ] **参照制約:** `request template` は、定義された `customerType` のいずれかを参照していること。
- [ ] **文体対応:** 客タイプ（`customerType`）によって、同じ条件であっても文体（テキスト）が変化するロジックが適用されること。

---
**補足:**
本仕様書は、上記定義に基づき、クイズ生成ロジックが正しく動作していることを検証するためのテストケース設計の基礎となる。
